توفّر Lerix خادم [MCP](https://modelcontextprotocol.io) عن بُعد حتى يتمكن وكيل
برمجي بالذكاء الاصطناعي من العمل ببيانات Lerix الحقيقية الخاصة بك، بدلاً من
نسخ المعرّفات ومفاتيح SDK يدويًا بينكما. يقوم الوكيل بتسجيل الدخول كأنه أنت،
عبر تسجيل دخول عادي بالمتصفح — لا يرى أو يخزّن كلمة المرور أو مفتاح API أبدًا،
ولا يمكنه رؤية أو تغيير أي شيء لا يملك حسابك بالفعل صلاحية للوصول إليه.

<Note>
  كل إجراء كتابة (إنشاء مشروع، حل مشكلة، إلخ) يتطلب من الوكيل تمرير علامة
  تأكيد صريحة، وهو ما لن يفعله وكيل مصمم جيدًا إلا بعد سؤالك أولاً. إجراءات
  القراءة (عرض المؤسسات، المشاريع، المشكلات) لا تتطلب تأكيدًا.
</Note>

## ربط Claude Code

```bash
claude mcp add --transport http lerix https://mcp.lerix.dev/mcp
```

بعد ذلك، في جلسة Claude Code، شغّل:

```
/mcp
```

اختر **lerix** — سيفتح المتصفح شاشة موافقة Lerix، حيث تسجّل الدخول (أو تستخدم
جلسة موجودة) وتوافق على الاتصال. يقوم Claude Code بتخزين الرمز وتحديثه تلقائيًا؛
تحتاج للقيام بهذا مرة واحدة فقط لكل جهاز.

إذا كنت تفضّل تثبيته كإضافة كاملة (تتضمن مهارة تُرتّب الأدوات لسير العمل
الشائعة، مثل ربط مشروع من البداية إلى النهاية):

```
/plugin marketplace add lerix-dev/lerix-mcp-plugin
/plugin install lerix@lerix
```

## ربط Replit

في Replit Agent: **Integrations ← MCP Servers ← + Add MCP server**، ثم الصق:

```
https://mcp.lerix.dev/mcp
```

يكتشف Replit إعدادات OAuth تلقائيًا ويرشدك لنفس خطوة تسجيل الدخول بالمتصفح.

## عملاء MCP آخرون

أي عميل يدعم خادم MCP عن بُعد عبر HTTP مع OAuth 2.1 (تسجيل عميل ديناميكي +
PKCE) يمكنه الاتصال بنفس الطريقة — وجّهه إلى `https://mcp.lerix.dev/mcp` وأكمل
تسجيل الدخول عند الطلب. لا يوجد مفتاح API لإنشائه أو لصقه.

## ما الذي يمكنه فعله

**القراءة** (لا تتطلب تأكيدًا):

| الأداة | ماذا تفعل |
|---|---|
| `list_organizations` | المؤسسات التي تنتمي إليها |
| `list_projects` | المشاريع في مؤسسة ما |
| `list_issues` | قائمة مشكلات مُصنَّفة وقابلة للتصفية لمشروع ما |
| `get_issue_details` | تتبع الخطأ، عدد التكرارات، الأجهزة المتأثرة لمشكلة واحدة |
| `search_events` | أعداد التكرارات الخام مجمّعة حسب النوع/الخطورة/اليوم |
| `get_usage_stats` | إحصاءات تسليم الإشعارات والأجهزة/الجغرافيا لمشروع ما |
| `list_topics` | مواضيع الإشعارات المُعدّة لمشروع ما |

**الإنشاء / الربط** (يتطلب تأكيدًا):

| الأداة | ماذا تفعل |
|---|---|
| `create_organization` | إنشاء مؤسسة جديدة تمامًا، مملوكة لك |
| `link_project` | العثور على مشروع أو إنشاؤه، وإرجاع مقطع تهيئة SDK حقيقي لإطار العمل المكتشف |
| `create_topic` | إنشاء موضوع إشعارات |

**الكتابة** (يتطلب تأكيدًا):

| الأداة | ماذا تفعل |
|---|---|
| `resolve_issue` | وضع علامة "تم الحل" على مشكلة |
| `assign_issue` | إسناد مشكلة إلى عضو فريق |

## ملاحظات أمنية

- كل الوصول مُقيّد بصلاحيات المؤسسة/المشروع الحالية الخاصة بك — لا يمكن
  للوكيل رؤية أو تغيير أي شيء لا يستطيع حسابك الوصول إليه أصلًا.
- لا شيء يتصل به الوكيل يمكنه قراءة كلمة مرورك. يتم تسجيل الدخول على
  `app.lerix.dev` نفسه، بنفس بيانات الدخول التي تستخدمها بالفعل.
- لفصل عميل ما، أزل الخادم منه مباشرة (مثل `claude mcp remove lerix`). إذا
  كنت تعتقد أن رمزًا معينًا قد تم اختراقه، تواصل مع
  [support@lerix.dev](mailto:support@lerix.dev).
