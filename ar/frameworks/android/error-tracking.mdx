## مقدمة

يلتقط Lerix الأخطاء والأعطال من تطبيق Android الأصلي (native) الخاص بك لتتمكّن من تصحيح المشاكل بشكل أسرع. بعد إتمام [تثبيت Android](/ar/frameworks/android/installation)، استخدم `Lerix.throwError` لإرسال أخطاء مخصّصة أو استثناءات ملتقطة إلى لوحة التحكم — أما الأعطال غير الملتقطة فتُلتقط تلقائياً، دون الحاجة لأي كود إضافي.

<Note>
  تأكّد من تهيئة الـ SDK عبر `Lerix.initialize()` قبل الإبلاغ عن الأخطاء.
</Note>

## الإبلاغ عن خطأ

استخدم `Lerix.throwError` للإبلاغ عن خطأ يدوياً. هذا مفيد عندما تلتقط استثناءً بنفسك وتريد إرساله إلى Lerix مع سياق إضافي.

```kotlin
import com.lerix.sdk.Lerix
import com.lerix.sdk.models.BugSeverity
import com.lerix.sdk.models.BugType

try {
    riskyOperation()
} catch (e: Exception) {
    Lerix.throwError(
        issue = e.toString(),
        stack = e.stackTrace.map { it.toString() },
        type = BugType.RUNTIME_ERROR,
        severity = BugSeverity.HIGH,
        metadata = mapOf("userId" to "123", "action" to "payment", "amount" to 100),
    )
}
```

### المعاملات (Parameters)

| المعامل | النوع | مطلوب | الوصف |
|-----------|------|----------|-------------|
| `issue` | `String` | نعم | رسالة الخطأ أو وصفه |
| `stack` | `List<String>` | لا | أطر تتبّع المكدس (Stack trace) — مرّر `e.stackTrace.map { it.toString() }` للحصول على أطر الاستثناء الملتقط |
| `type` | `BugType` | لا | تصنيف نوع الخطأ (الافتراضي: `RUNTIME_ERROR`) |
| `severity` | `BugSeverity` | لا | مستوى الخطورة (الافتراضي: `MEDIUM`) |
| `metadata` | `Map<String, Any?>?` | لا | سياق إضافي يُرفق بالتقرير |

### قيم `BugType`

| القيمة | الوصف |
|-------|-------------|
| `RUNTIME_ERROR` | استثناء غير معالَج يُرمى أثناء التشغيل |
| `LOGIC_BUG` | سلوك غير صحيح لا يرمي استثناءً |
| `UI_BUG` | خلل بصري أو في التخطيط (layout) |
| `NETWORK_ERROR` | طلب شبكة فاشل أو مُشوَّه |
| `PERFORMANCE` | بطء، تقطّع (jank)، أو استهلاك موارد مفرط |
| `COMPATIBILITY` | خلل يظهر على جهاز أو إصدار نظام أو منصة محدّدة |
| `VALIDATION_ERROR` | إدخال غير صالح تجاوز التحقق رغم أنه لا ينبغي |
| `SECURITY` | خلل متعلّق بالأمان |
| `CRASH` | توقّف التطبيق بشكل غير متوقّع |
| `UNKNOWN` | لا شيء مما سبق |

### قيم `BugSeverity`

| القيمة | الوصف |
|-------|-------------|
| `CRITICAL` | يعطّل وظيفة أساسية أو يؤثّر على جميع المستخدمين |
| `HIGH` | تأثير كبير، لكن يوجد حل بديل (workaround) |
| `MEDIUM` | ملحوظ لكن تأثيره محدود |
| `LOW` | بسيط أو شكلي |
| `UNKNOWN` | لم يتم تقييم الخطورة بعد |

## الالتقاط التلقائي للأعطال

يُثبّت `Lerix.initialize()` معالج أعطال (crash handler) تلقائياً، يلفّ الدالة العامة `Thread.setDefaultUncaughtExceptionHandler` في Java/Kotlin — أي استثناء غير ملتقط على أي خيط (thread) يُلتقط، بغضّ النظر عن الخيط الذي حدث فيه.

لا يمكن للعطل إجراء استدعاء شبكة بشكل موثوق — فالعملية (process) تكون بصدد الإنهاء — لذا يُكتب التقرير إلى القرص بشكل متزامن (synchronous) لحظة العطل، ثم يُرسَل تلقائياً في *المرة التالية* لتشغيل تطبيقك، مصنَّفاً كـ `type: CRASH, severity: CRITICAL`. لا تحتاج لفعل أي شيء لاستلامه؛ سيظهر في لوحة التحكم عند التشغيل التالي.

لتعطيل هذه الميزة (مثلاً إذا كان تطبيقك يملك بالفعل نظام تتبع أعطال خاصاً به وتريد فقط استدعاءات `throwError` اليدوية):

```kotlin
Lerix.initialize(
    context = this,
    apiKey = "your-api-key",
    projectId = "your-project-id",
    enableCrashReporting = false,
)
```

### تحقّق من التكامل

أرسل خطأً تجريبياً للتأكّد من أن كل شيء يعمل:

```kotlin
Lerix.throwError("Test error")
```

ثم افتح [لوحة التحكم](https://app.lerix.dev) — يجب أن يظهر الخطأ خلال ثوانٍ.

## ترشيح الأخطاء

يتطلّب الـ SDK الخاص بـ Android بالإصدار 1.2.0 أو أحدث.

احذف الأخطاء المزعجة أو نظّف البيانات قبل أن تغادر الجهاز. ينطبق الترشيح
على كل خطأ يرسله الـ SDK: `Lerix.throwError` والأعطال غير الملتقطة (يُفحص
العطل عند إرساله في التشغيل التالي).

```kotlin
Lerix.initialize(
    context = this,
    apiKey = "YOUR_PROJECT_API_KEY",
    projectId = "YOUR_PROJECT_ID",
    // Dropped when the message contains any of these (case-insensitive).
    ignoreErrors = listOf("Read timed out", "Software caused connection abort"),
    // Dropped when the message matches any of these regexes (containsMatchIn).
    ignoreErrorPatterns = listOf(Regex("^java\\.net\\.\\w+Exception")),
    // Runs after the ignore lists. Return the event (optionally modified) to
    // send it, or null to drop it.
    beforeSend = { event ->
        if (event.metadata?.get("debugOnly") == true) null
        else event.copy(message = event.message.replace(Regex("token=\\S+"), "token=[redacted]"))
    },
)
```

- تعمل `ignoreErrors` (`List<String>`) و`ignoreErrorPatterns` (`List<Regex>`)
  أولاً. تُتجاوَز عناصر `ignoreErrors` الفارغة أو التي تحتوي مسافات فقط.
- ثم تستقبل `beforeSend` كائن `LerixErrorEvent` بالحقول `message` و`stack`
  و`type` و`severity` و`metadata`. أعِده (معدّلاً أو كما هو) لإرساله، أو أعِد
  `null` لحذفه. تُستدعى على خيط (thread) في الخلفية.
- إذا رمت `beforeSend` استثناءً، يُرسَل الحدث الأصلي ويُبتلَع الاستثناء
  (ويُسجَّل في `debugMode`).
- الرسالة التي تطابقها هي عنوان المشكلة، وتتضمّن صنف الخطأ.

كما يجمّع Lerix الأخطاء المتكرّرة في مشكلة واحدة ويرشّح الضوضاء الشائعة على
الخادم، لكل إصدارات الـ SDK. راجع
[كيف تُجمَّع الأخطاء في مشكلات](/ar/modules/error-tracking#how-errors-are-grouped-into-issues).
