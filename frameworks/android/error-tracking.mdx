## Introduction

Lerix captures errors and crashes from your native Android app so you can debug issues faster. After you complete the [Android installation](/frameworks/android/installation), use `Lerix.throwError` to send custom errors or caught exceptions to your dashboard — uncaught crashes are captured automatically, with no extra code required.

<Note>
  Make sure you have initialized the SDK with `Lerix.initialize()` before reporting errors.
</Note>

## Report an error

Use `Lerix.throwError` to manually report an error. This is useful when you catch an exception yourself and want to send it to Lerix with extra context.

```kotlin
import com.lerix.sdk.Lerix
import com.lerix.sdk.models.BugSeverity
import com.lerix.sdk.models.BugType

try {
    riskyOperation()
} catch (e: Exception) {
    Lerix.throwError(
        issue = e.toString(),
        stack = e.stackTrace.map { it.toString() },
        type = BugType.RUNTIME_ERROR,
        severity = BugSeverity.HIGH,
        metadata = mapOf("userId" to "123", "action" to "payment", "amount" to 100),
    )
}
```

### Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `issue` | `String` | Yes | Error message or description |
| `stack` | `List<String>` | No | Stack trace frames — pass `e.stackTrace.map { it.toString() }` for a caught exception's frames |
| `type` | `BugType` | No | Bug classification (default: `RUNTIME_ERROR`) |
| `severity` | `BugSeverity` | No | Severity level (default: `MEDIUM`) |
| `metadata` | `Map<String, Any?>?` | No | Additional context to attach to the report |

### `BugType` values

| Value | Description |
|-------|-------------|
| `RUNTIME_ERROR` | An unhandled exception thrown at runtime |
| `LOGIC_BUG` | Incorrect behavior that doesn't throw |
| `UI_BUG` | A visual or layout defect |
| `NETWORK_ERROR` | A failed or malformed network request |
| `PERFORMANCE` | Slowness, jank, or excessive resource use |
| `COMPATIBILITY` | Breaks on a specific device, OS version, or platform |
| `VALIDATION_ERROR` | Invalid input passed validation it shouldn't have |
| `SECURITY` | A security-relevant defect |
| `CRASH` | The app terminated unexpectedly |
| `UNKNOWN` | None of the above |

### `BugSeverity` values

| Value | Description |
|-------|-------------|
| `CRITICAL` | Blocks core functionality or affects all users |
| `HIGH` | Serious impact, but a workaround exists |
| `MEDIUM` | Noticeable but limited impact |
| `LOW` | Minor or cosmetic |
| `UNKNOWN` | Severity not yet assessed |

## Automatic crash capture

`Lerix.initialize()` installs a crash handler by default, wrapping Java/Kotlin's global `Thread.setDefaultUncaughtExceptionHandler` — any uncaught exception on any thread is captured, regardless of which thread it occurs on.

A crash can't reliably make a network call — the process is already terminating — so the report is written to disk synchronously at crash time, then sent automatically the *next* time your app launches, tagged `type: CRASH, severity: CRITICAL`. You don't need to do anything to receive it; it shows up in the dashboard on the following launch.

To disable it (e.g. if your app already has its own crash reporter and you only want manual `throwError` calls):

```kotlin
Lerix.initialize(
    context = this,
    apiKey = "your-api-key",
    projectId = "your-project-id",
    enableCrashReporting = false,
)
```

### Verify the integration

Throw a test error to confirm everything is working:

```kotlin
Lerix.throwError("Test error")
```

Then open your [dashboard](https://app.lerix.dev) — the error should appear within seconds.

## Filtering errors

Requires the Android SDK 1.2.0 or later.

Drop noisy errors or scrub data before it leaves the device. Filtering
applies to every error the SDK sends: `Lerix.throwError` and uncaught
crashes (checked when the crash is sent on the next launch).

```kotlin
Lerix.initialize(
    context = this,
    apiKey = "YOUR_PROJECT_API_KEY",
    projectId = "YOUR_PROJECT_ID",
    // Dropped when the message contains any of these (case-insensitive).
    ignoreErrors = listOf("Read timed out", "Software caused connection abort"),
    // Dropped when the message matches any of these regexes (containsMatchIn).
    ignoreErrorPatterns = listOf(Regex("^java\\.net\\.\\w+Exception")),
    // Runs after the ignore lists. Return the event (optionally modified) to
    // send it, or null to drop it.
    beforeSend = { event ->
        if (event.metadata?.get("debugOnly") == true) null
        else event.copy(message = event.message.replace(Regex("token=\\S+"), "token=[redacted]"))
    },
)
```

- `ignoreErrors` (`List<String>`) and `ignoreErrorPatterns` (`List<Regex>`)
  run first. Empty or whitespace-only `ignoreErrors` entries are skipped.
- `beforeSend` then gets a `LerixErrorEvent` with `message`, `stack`, `type`,
  `severity` and `metadata`. Return it (changed or not) to send it, or `null`
  to drop it. It is called on a background thread.
- If `beforeSend` throws, the original event is sent and the exception is
  swallowed (logged in `debugMode`).
- The message you match against is the issue title, which includes the error
  class.

Lerix also groups repeated errors into one issue and filters common noise on
the server, for every SDK version. See
[How errors are grouped into issues](/modules/error-tracking#how-errors-are-grouped-into-issues).
